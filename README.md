# Django-приложение — агрегатор Bash-скриптов, которые специалист ТПХ использует в повседневной работе

Запуск скриптов выполняется через curl. Для работы с сервисом достаточно скопировать подготовленную команду, подставить значения аргументов и запустить команду в терминале.

Сервис доступен на странице: https://tph.lzy.su

Сервис запущен в demo-аккаунте. Актуальный логин и пароль для доступа всегда можно посмотреть в `.env`-файле. Не нашёл более удобного способа сообщать доступы, если пароль ротируется.

Сервис закрыт паролем, так как в Bash-скриптах используются внутренние утилиты и видны пути к логам. Не думаю, что выставлять даже такие данные наружу — хорошая идея. По этой же причине в публичном репозитории хранятся только demo-скрипты.

Возможности:
- все основные скрипты в одном месте (пока не все)
- меньше печатать руками
- удобная работа с логами в архивах. Не нужно вручную заменять **cat** на **zcat** и править имя файла лога **.1.gz/.2.gz** и т.д. Достаточно указать ключ `-d 1`, чтобы обработать лог `access.log.1.gz`
- одна команда может выполнять несколько действий. Например, скрипт проверки бана IP клиента на сервере делает три действия — проверяет блокировку IP, выводит пять последних записей для проверяемого IP из **ddos-лога** и **fail2ban-лога**
- скрипты умеют работать с кириллическими доменами

Приложение разрабатывалось так, что новый Bash-скрипт может добавить любой желающий специалист без дополнительных настроек и правки кода приложения.

Чтобы добавить новый скрипт, достаточно положить подготовленный `.yml`-файл в каталог `~/www/<site.ru>/lazy_bash/scripts/`. Перезапуск приложения не требуется, скрипт подхватывается автоматически.

Небольшой пример:
```
title: "Just Hello World"
description: "Simple demo .yml"
args: ""
version: 1.0.0
author: "Cool Author"
tags: ""
content: |
  #!/bin/bash
  echo "Hello World"
```
Пояснение:

`title` — Название скрипта в веб-интерфейсе приложения.

`description` — Краткое описание того, что и как делает скрипт. Видно в веб-интерфейсе.

`args` — Плейсхолдеры аргументов, которые подставляются в команду вызова скрипта. Видны в веб-интерфейсе.

`version` — Номер версии скрипта. Скрипты могут содержать баги, изменения стоит версионизировать.

`author` — Автор скрипта. Нашёл баг или есть предложения — понятно, кому сообщить.

`tags` — Метки для сортировки, если количество скриптов разрастётся. Пока нигде не используются.

`content` — Содержимое Bash-скрипта.

Посмотреть реальные примеры можно на простых демо-скриптах `curl_01_weather.yml` (без аргументов) и `curl_02_domain_timing_stats.yml` (использует аргументы).

## Разработка и отладка Bash-скриптов

Для разработки Bash-скриптов можно использовать экземпляр приложения, развёрнутый по адресу https://playground.lzy.su. Просто положите подготовленный `.yml`-файл в папку со скриптами и можно тестировать и отлаживать код. Этот способ избавляет от необходимости запускать приложение локально или разворачивать свой экземпляр на хостинге.

Для работы с удалённой папкой удобно использовать утилиту `sshfs`. Она позволяет работать с файлами на сервере так, как будто они лежат на локальном компьютере.

Установите `sshfs` (Debian/Ubuntu):
```
sudo apt install sshfs
```
Предварительно подготовьте папку на локальном ПК:
```
mkdir ~/remote-app
```
Смонтируйте папку:
```
sshfs u1234567@123.123.123.123:/var/www/u123456/data/path/to/folder/ ~/remote-app/
```
Теперь в каталоге `~/remote-app/` можно запускать любимый редактор кода и работать.

### Файл common.sh

Файл common.sh содержит функции, которые можно переиспользовать в собственных Bash-скриптах. Функция `to_punycode()` конвертирует кириллические домены в Punycode. Функция `run()` формирует вывод результата для удобного восприятия в консоли, но сохраняет возможность передать результат работы вызванного скрипта в конвейер для дальнейшей обработки.

## Как Django-приложение запустить локально

Склонируйте репозиторий:
```
git clone git@github.com:YuriyCherniy/lazy-bash.git
```
Перейдите в рабочую директорию:
```
cd ./lazy-bash/app/
```
Убедитесь, что версия Python не ниже 3.10 (требование Django 5.2):
```
python3 --version
```
Создайте виртуальное окружение:
```
python3 -m venv .venv
```
Активируйте виртуальное окружение:
```
source .venv/bin/activate
```
Установите зависимости:
```
pip install -r requirements.txt
```
Скопируйте `.env.example` в `.env`:
```
cp .env.example .env
```
Запустите сервер:
```
./manage.py runserver
```
Готово. Перейдите по адресу: http://127.0.0.1:8000/

## Деплой собственного экземпляра приложения на хостинге

Деплой приложения на хостинге автоматизирован плейбуками Ansible. Ansible runner работает как Docker-контейнер на локальном компьютере.

### Требования локальной машины для успешного деплоя

- Установленные Docker Engine и Docker Compose (проверено на Docker version 29.3.0 и Docker Compose version v5.1.0)
- Настроенный SSH-доступ по ключу к услуге хостинга

### Подготовка Ansible runner

- Склонируйте репозиторий:
```
git clone git@github.com:YuriyCherniy/lazy-bash.git
```
- Перейдите в каталог с compose-файлом. Все команды выполняются из этого каталога:
```
cd ./lazy-bash/ansible/
```
- Прверьте путь к приватному SSH-ключу в файле `docker-compose.yml`. Скорректируйте, если путь отличается от следующего:
```
    volumes:
      - ${HOME}/.ssh/id_rsa:/root/.ssh/id_rsa:ro
```
Контейнер Ansible runner использует тот же ключ для подключения к хостингу, что и у локальной машины.
- Соберите образ:
```
docker compose build
```
- Проверьте созданный образ:
```
docker compose run --rm ansible-runner ansible --version
```
### Подготовка файла Ansible vault.yml

- Создайте vault
```
docker compose run --rm -it ansible-runner \
  ansible-vault create group_vars/all/vault.yml
```
- Заполните переменные:
```
vault_hosting_user: "hosting-user-u1234567"
vault_hosting_password: "hosting-password"
vault_hosting_email: "admin@example.com"
vault_hosting_ip: "123.123.123.123"
vault_hosting_domain: "lazy-bash.example.com"
vault_basic_auth_user: "basic-auth-user"
vault_basic_auth_password: "basic-auth-password"
vault_django_secret_key: "django-secret-key"
vault_django_debug: "False"
```
Скорректировать значения в vault.yml можно командой:
```
docker compose run --rm -it ansible-runner \
  ansible-vault edit group_vars/all/vault.yml
```
- Проверьте инвентарь перед деплоем:
```
docker compose run --rm -it ansible-runner \
  ansible-inventory --list --ask-vault-pass
```
### Запуск деплоя
```
docker compose run --rm -it ansible-runner \
  ansible-playbook main.yml --ask-vault-pass
```
Деплой выполняет следующие действия:
- Добавляет домен в ispmanager
- Настраивает basic auth
- Удаляет стандартный index.html
- Создаёт виртуальное окружение Python
- Доставляет код из git
- Устанавливает зависимости
- Создаёт .env
- Собирает статику
- Настраивает Passenger
Вручную необходимо установить только SSL-сертификат после развёртывания приложения.

### Ротация пароля basic auth

Пароль basic auth хранится в vault и используется приложением через `.env`
и Apache через `.htpasswd`. Ротация выполняется отдельным плейбуком `rotate_basic_auth.yml`.

Плейбук берёт новый пароль из поля `vault_basic_auth_password` в
`group_vars/all/vault.yml`, перезаписывает `.htpasswd` и `.env` на сервере и
перезапускает Passenger.

Алгоритм ротации:

- отредактируйте `vault.yml`, указав новый пароль:
```
docker compose run --rm -it ansible-runner \
  ansible-vault edit group_vars/all/vault.yml
```
- запустите плейбук ротации:
```
docker compose run --rm -it ansible-runner \
  ansible-playbook playbooks/rotate_basic_auth.yml --ask-vault-pass
```
